# 在线更新发布

客户端只查询本仓库的最新正式 Release，优先读取发布文件直链。旧版没有更新清单时使用 GitHub API；接口限流时通过最新发布页的重定向核对版本。玩家点击下载后，更新文件保存在安装目录的 `Updates` 文件夹；下次通过根目录 `MabiSync.exe` 启动时安装。配置目录和 `Config/乐器列表.txt` 不参与替换。

## 制作发布文件

1. 将应用的 Version 改为本次正式版本号。
2. 使用 `tools/Build-Preview.ps1 -Release -Label <版本号> -UpdateBaselineDirectory <旧运行版目录>` 打包。运行时与许可证参数沿用常规发布命令。可以通过参数数组指定多个旧版本目录。
3. 发布完整 ZIP 及其校验文件，同时上传生成的 `MabiSync-<版本号>-update-assets` 目录中的全部文件，包括 `MabiSync-update.json`、增量 ZIP 和各自的校验文件。
4. 先创建草稿，等所有文件上传完成、GitHub API 的 asset digest 可用后，再发布为最新正式版。

旧版本目录用于逐文件比较；每个增量 ZIP 只保存有变化或新增的文件。更新清单列出新版全部应用及文档文件，因此旧版多余文件会随目录替换移除。无匹配增量包或本机基础文件被改动时，客户端使用同一个 Release 的完整 ZIP。

## 检查与回退

`tools/Test-Quick.ps1` 包括版本比较、只查询不下载、增量选择、校验失败、下载取消、目录越界、完整包回退，以及启动器安装和回退测试。打包后还会验证自带运行时和本地房间服务。

安装前重新核对全部暂存文件；替换 App、Docs 后运行隔离的启动检查，通过后才删除备份。启动检查失败或上次安装中断时，启动器恢复备份后打开原版。用户可在工具状态区查看结果。

根目录启动器使用 Windows 10/11 自带的 .NET Framework 4.x；主程序继续携带 .NET 8 运行时。启动器协议固定为 1，本轮在线更新只替换 App 和 Docs。将来若更换启动器协议，应要求下载完整包，避免通过旧启动器安装不兼容版本。

0.1.4 及之前版本没有在线更新入口，需要先下载一次带新启动器的完整包。预览版可以检查正式版，较旧正式版不会覆盖较新预览版。
